# Translating the studio

Every user-facing string in Stone Author resolves through one function. English is the source of truth,
ships inline, and is the only pack the app needs to run. Adding a language never means editing the studio.

Companion docs: [`architecture.md`](architecture.md) (how the studio is built),
[`capabilities.md`](capabilities.md) (what each control does).

## The seam

`<script id="sa-i18n">` defines `window.SA_I18N` **before** the studio runs, so the first painted frame is
already translated — there is no English flash.

| call | what it does |
|---|---|
| `SA_I18N.T(key, vars)` | resolve a key; `{name}` placeholders filled from `vars`; falls back to English, then to the key itself |
| `SA_I18N.register(lang, obj, label)` | add a pack at runtime |
| `SA_I18N.setLang(lang)` | switch, persist to `localStorage`, re-apply, notify listeners |
| `SA_I18N.onChange(fn)` | called after every switch |
| `SA_I18N.missing` | keys asked for that no pack had — empty on a healthy build |

Inside the studio the function is bound as **`TR`**, not `T` — the studio's own `T` is the tile settings
object, and `const T = SA_I18N.T` shadows it. (That collision is a syntax error, not a subtle bug, so it
surfaces immediately; the name is deliberate all the same.)

The studio's markup carries the keys:

- `data-i18n="key"` — replaces `textContent`
- `data-i18n-html="key"` — replaces `innerHTML`, for prose that contains `<b>`
- `data-i18n-attr="aria-label=key;title=key"` — one or more attributes

Panels the studio **generates** (layers, folders, the Selected bar, the colour editor) hold no markup to
re-label, so `onChange` rebuilds them rather than patching them.

## Counts go through the pack, never through `+ 's'`

A value may be a string, or an object of plural forms chosen with `Intl.PluralRules` **for the active
language**:

```json
"hint.deleted-layer-marks": {
  "one":   "Deleted {name} and {n} mark.",
  "other": "Deleted {name} and {n} marks."
}
```

`"mark" + (n > 1 ? "s" : "")` is an English rule. Polish needs three forms and Arabic six — in Polish, 2
and 22 take *few* while 5 takes *many*, which no amount of `s` can express. A pack supplies whichever
forms its language has; English supplies `one` and `other`.

## Adding a language

Two ways, and the studio does not care which:

1. **A file** — drop `i18n/<lang>.json` beside the page. `SA_I18N.setLang` fetches it on demand.
2. **Inline** — call `SA_I18N.register('it', {...}, 'Italiano')`, for a single-file build with no fetch.

The language menu builds itself from the registered packs, so neither route means touching studio code.
Initial language is `?lang=`, then the remembered choice, then `navigator.languages`, then English.

## Context for translators — `i18n/_glossary.json` and `i18n/_context.json`

**These words are nasty for blind translation.** Not mainly because they are specialist, but because most
of them are ordinary English carrying a domain meaning. A translator who picks the dictionary's first sense
produces something that reads perfectly and is wrong:

| the studio's word | what it means here | what a blind translation gives |
|---|---|---|
| gauge | a vein's thickness | a measuring instrument |
| family | a stone's character set | relatives |
| ground | the base material *under* everything | the slab's visible surface |
| matrix | the fine rock between clasts | a mathematical array |
| island | a region shielded from the warp | a landmass |
| warp | field distortion | the threads in weaving |
| moon | a gravitational body deforming the stone | a month, or lunar imagery |
| web | the crack network | a web page |
| identity | the per-*artifact* view | who someone is |
| spectrum | which artifacts are observable at all | a brightness or a broad range |

So context ships as **source**, not as a favour:

- **`_glossary.json`** — 55 terms in two groups. `homographs` are the table above: each says what the
  studio `means`, and explicitly `notThe` reading to avoid. `termsOfArt` are the genuine specialist words
  (stylolite, boudinage, en-echelon, breccia, clast, drusy, kerf, grout, reeded, fresnel…). Every entry
  carries a **ruling**: `keep` (leave the English — *boudinage*, *en-echelon*, *fresnel* are already
  loanwords used untranslated), `translate`, or `trade` (use your language's established stone, glass or
  masonry term). **kerf** is the worked example: it is the material *loss between the resulting edges*,
  not the cut path, and any term meaning "cut line" is wrong even where a trade uses it loosely — which
  is why *trait de scie* was withdrawn as a suggestion, since it names both the saw and the line.
  Foreign-language equivalents in the hints are **candidates to verify, never rulings**; they were written
  from general knowledge and at least one was wrong on first pass.
- **`_context.json`** — one entry per key, all 321. `where` says what the string is on screen, derived
  from the markup rather than guessed ("title of a collapsible section in the right-hand rail",
  "transient hint line under the tool palette", "tooltip in the Selected bar, under Layers").
  `terms` lists the glossary terms that string contains — 143 of the 321 carry at least one.
  `placeholders` says what each `{name}`/`{n}` stands for, including that a layer name the user typed is
  **placed, never translated**. `plural` marks the seven count strings.

The rule this encodes: if a term has no settled equivalent in a language, **keep the English rather than
coin one** — an invented word is worse than an untranslated one, because a mason searching for it finds
nothing.

Three definitions are written deliberately against their nearest neighbour, because the neighbour is what
a translator will drift into:

- **ground** is the base material *under* the authored structures. Stone Author has a real depth model, so
  "surface" means the polished coat at the *other* end of the stack — the glossary says so explicitly.
- **spectrum** is not a brightness. `emit()` returns nothing unless the light sits within `SPX_TOL` of an
  artifact's activation value, and a non-emitting artifact goes dark against the black ground. Sweeping it
  makes sets of artifacts *appear and disappear*: it is an observation state, and the entry forbids any
  word suggesting intensity.
- **subsurface** and **back light** are separate, mutually exclusive render passes. Subsurface is light
  transport *inside* the stone; back light is illumination arriving from *behind* it. A translator reaching
  for "lit from within" collides the two, so each entry names the other and says which half it owns.

## Reviewing the glossary

The sheet is meant to be read and corrected before any locale exists — it is a semantic review, not
translation output. The definitions above were tightened this way: `moon` was a nickname for a drag tool
until Chris pointed out the tool *models a gravitating body*, which changed the ruling from "rename it
after what it does" to "use the astronomical word and specifically do not rename it". `ground`,
`identity` and `spectrum` were then re-derived from the implementation rather than from the old copy, and
`backlight`, `transmittance`, `emission` and `spotlight` were added because they were missing.

## What must NOT be translated

Two classes of string look user-facing and are not:

- **Archive members in the ORA/ZIP export** — `mimetype`, `stack.xml`, `data/`, `Thumbnails/thumbnail.png`.
  Translating these produces a corrupt file that no editor will open. They are deliberately left as
  literals and the gate's skip-list names them.
- **Terms of art**, which are a judgement call rather than a rule: *stylolite, boudinage, en-echelon,
  drusy, breccia, clast, kerf, fresnel, reeded*. Several are international (breccia is already Italian;
  stylolite is stylolithe / Stylolith across Europe), but where a language has no settled trade term, a
  coined translation is **worse than the English** — a mason searching for it will find nothing. Leave the
  English term rather than invent one, and note it in the pack.

## The gate — `tools/check-i18n.mjs`

```bash
node tools/check-i18n.mjs
```

Run on every change to the app, the packs or the gate itself (`.github/workflows/i18n.yml`). It fails on
the four ways a translated UI rots without anyone noticing:

1. a user-facing string in the markup that never got a key — it can never be translated
2. a key the studio asks for that no pack defines — the UI renders the key name
3. a pack that has drifted from English, missing keys or carrying stale ones
4. **a translation whose placeholders differ from English** — the quiet one: `"Deleted {name}"` translated
   without `{name}` silently loses the layer name at runtime and nothing throws
5. **an American spelling in the source English.** The UI is British — measured, not assumed: the
   user-facing prose runs 25 *colour* to 0 *color*. A stray *color*, *gray* or *geologic* is cheapest to
   catch before it has been translated eighteen times. Deliberately *not* flagged: **artifact**, which the
   studio uses throughout as the rendering term of art, and **-ize** endings, which are valid British
   (Oxford) spelling
6. a key with no translator context, context with no location, an undescribed placeholder, a cited term
   absent from the glossary, or a stale entry

Each of the four was verified to go red by introducing exactly that defect and confirming a non-zero exit,
then confirming the clean tree passes again.
